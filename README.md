# Personal Tools

A small local-first React + TypeScript PWA. Skincare and Oral Hygiene share a reusable Tool → Routine → Task model. No account, backend, runtime API calls, or paid services.

## Run

Requires Node 22.12+ (or a current supported Node release).

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Preview serves the production PWA at http://localhost:4173. The development server does not register a service worker. Open the production app once online to cache its assets; subsequent launches work offline.

## iPhone installation

Publish to an HTTPS address, open it in Safari, and choose Share → Add to Home Screen. Localhost on your computer is not your phone's localhost. The LAN HTTP preview is useful for layout testing but is not a secure origin for service workers on iPhone; use the HTTPS deployment for installation/offline testing.

## Deploy to Surge

```sh
npx surge login
npm run deploy -- personal-tools.surge.sh
```

Surge prompts for email/password in your terminal. Do not put credentials in source control. If this domain belongs to another account, choose a different domain. Once a domain is confirmed, put it in the root `CNAME` file or set `SURGE_DOMAIN` to reuse it with `npm run deploy`. Deploy always builds first. Hash navigation needs no server-side routing rules. This follows [Vite's static deployment guide](https://vite.dev/guide/static-deploy.html#surge).

## Commit, push, build, deploy

Git is initialized on `main`; no remote is configured. Configure your own remote before using the release command:

```sh
git remote add origin YOUR_REPOSITORY_URL
# Create your first commit, then establish the upstream:
git add .
git commit -m "Build Personal Tools PWA"
git push -u origin main
npm run release -- "Describe your changes" personal-tools.surge.sh
```

`release` requires an upstream, runs tests and builds, stages all non-ignored changes, commits if needed, pushes, then deploys the same build. Review your changes before running it. If publishing fails after the push, retry `npm run deploy`; these are separate services, not an atomic transaction. No automatic commits or external Git pushes have been performed during setup.

Cloudflare Workers, D1, notifications, and Cloudflare deployment are deliberately deferred. The standalone storage module is the replacement point for future sync; no unused Cloudflare scaffolding or credentials are required now.

## Structure

- `src/app`: shell, navigation, state and styling
- `src/components`: shared presentation
- `src/tools`: initial tool definitions; add another definition to `src/tools/index.ts`
- `src/routines`: types, daily completion logic, shared routine card
- `src/pages`: configuration editor
- `src/storage`: small IndexedDB adapter using `idb`
- `scripts`: explicit deployment and release commands
- `tests`: completion/undo, day isolation and persistent storage tests

Tool behavior is data-driven. Routine and task names can be edited; tasks and routines can be added or removed. IDs remain stable on rename. Deleted tasks retain their historical records. New tool definitions seed fresh installs; existing installs keep their saved configuration.

## Local data

IndexedDB stores configuration, theme, and activity on this browser origin. Every completion records the task/routine/tool IDs and name snapshots, local calendar day, and an ISO timestamp. Undo marks the activity with `undoneAt`; ticking again creates a fresh completion. Today resets by local date, checked on focus and every 30 seconds. History shows past records and undone completions.

Settings exports JSON backups. Restore/import is not implemented in this first version. Clearing browser data, switching domains, or removing site storage can lose your local records. Safari and an installed Home Screen app may use separate storage contexts; begin using the installed app before logging real routines. There is no synchronization between devices or tabs.

PWA assets are generated by `vite-plugin-pwa`/Workbox at build time. Icons are simple local placeholders. System fonts and bundled icons keep the app entirely self-contained. Production updates activate automatically; editing drafts should be saved before refreshing.
