# Personal Tools

A small local-first React + TypeScript PWA. Skincare and Oral Hygiene share a reusable Tool → Routine → Task model. No user accounts or paid services. Routines and activity stay local; a small Cloudflare Worker + D1 service sends reminders.

## Run

Requires Node 22.12+ (or a current supported Node release).

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Preview serves the production PWA at http://localhost:4173. The development server does not register a service worker. Open the production app once online to cache its assets; subsequent launches work offline.

## iPhone installation

Publish to an HTTPS address, open it in Safari, and choose Share → Add to Home Screen. Localhost on your computer is not your phone's localhost. The LAN HTTP preview is useful for layout testing but is not a secure origin for service workers on iPhone; use the HTTPS deployment for installation/offline testing.

## Deploy to Surge

```sh
npx surge login
npm run deploy -- personal-tools.surge.sh
```

Surge prompts for email/password in your terminal. Do not put credentials in source control. If this domain belongs to another account, choose a different domain. Once a domain is confirmed, put it in the root `CNAME` file or set `SURGE_DOMAIN` to reuse it with `npm run deploy`. Deploy always builds first. Hash navigation needs no server-side routing rules. This follows [Vite's static deployment guide](https://vite.dev/guide/static-deploy.html#surge).

## Commit, push, build, deploy

Git is initialized on `main`; no remote is configured. Configure your own remote before using the release command:

```sh
git remote add origin YOUR_REPOSITORY_URL
# Create your first commit, then establish the upstream:
git add .
git commit -m "Build Personal Tools PWA"
git push -u origin main
npm run release -- "Describe your changes" personal-tools.surge.sh
```

`release` requires an upstream, runs tests and builds, stages all non-ignored changes, commits if needed, pushes, then deploys the same build. Review your changes before running it. If publishing fails after the push, retry `npm run deploy`; these are separate services, not an atomic transaction. The release command deploys the Cloudflare reminder Worker and the Surge frontend.

Cloudflare handles notification settings only. Task/activity synchronization is still deferred.

## Structure

- `src/app`: shell, navigation, state and styling
- `src/components`: shared presentation
- `src/tools`: initial tool definitions; add another definition to `src/tools/index.ts`
- `src/routines`: types, daily completion logic, shared routine card
- `src/pages`: configuration editor
- `src/storage`: small IndexedDB adapter using `idb`
- `scripts`: explicit deployment and release commands
- `tests`: completion/undo, day isolation and persistent storage tests

Tool behavior is data-driven. Routine and task names can be edited; tasks and routines can be added or removed. Routines and individual tasks have a Repeat setting: every day, every other day, selected weekdays, or every N days (2–365). Interval schedules use a start date and local calendar days, continue across week/month boundaries and daylight saving, and do not shift when a task is skipped. A task appears only when both its own schedule and its parent routine are due; off-day tasks are excluded from progress. Task repeat controls expand under “Change repeat” in the editor. Existing weekday schedules remain supported. On the first load after this update, the built-in Epiduo task switches to every other day, anchored to its latest active completion (or today if none exists). This migration saves once and preserves subsequent user edits and activity. IDs remain stable on rename. Deleted tasks retain their historical records. New tool definitions seed fresh installs; existing installs keep their saved configuration.

## Local data

IndexedDB stores configuration, theme, and activity on this browser origin. Every completion records the task/routine/tool IDs and name snapshots, local calendar day, and an ISO timestamp. Undo marks the activity with `undoneAt`; ticking again creates a fresh completion. Today resets by local date, checked on focus and every 30 seconds. History shows past records and undone completions.

Settings exports JSON backups. Restore/import is not implemented in this first version. Clearing browser data, switching domains, or removing site storage can lose your local records. Safari and an installed Home Screen app may use separate storage contexts; begin using the installed app before logging real routines. There is no routine/activity synchronization between devices or tabs.

PWA assets are generated by `vite-plugin-pwa`/Workbox at build time. Icons are simple local placeholders. System fonts and bundled icons keep the app entirely self-contained. Production updates activate automatically; editing drafts should be saved before refreshing.

## Notifications

The Cloudflare Worker is `personal-tools-reminders`; D1 holds push subscriptions, device tokens, schedule preferences, and last attempted reminder dates. The frontend stays on Surge. The public Worker URL is in `.env.production` and can be overridden with `VITE_REMINDERS_URL`.

On your iPhone, open the Home Screen app, go to Settings → Notifications, enter the device setup code from ignored `.dev.vars` (`SETUP_KEY`), and tap Enable notifications. Allow the iOS prompt, then use Send test notification. Defaults are **08:00 / 19:00, Europe/London**. Change times/timezone or turn off daily reminders and tap Save reminders. Disconnect removes that device's subscription from the server. Notifications require iOS 16.4+, installation to the Home Screen, and an internet connection. Focus settings and network availability may delay delivery.

Cron runs every minute in UTC; the Worker checks the configured local time using IANA timezones, including UK daylight saving. It claims a date/period before sending to prevent duplicate sends. Delivery is best effort: a failed send is logged and not retried that day; a delayed/missed scheduler invocation can miss a reminder. These are generic reminders regardless of whether tasks are already done, since completion records remain local. Notification taps open Today. Apple/Google/Mozilla push services transport encrypted notifications; no third-party notification vendor is used.

Secrets are in ignored, private `.dev.vars` locally and Cloudflare Worker secrets remotely. Do not regenerate VAPID keys after connecting devices. Setup codes are reusable for connecting your devices; protect them and never put them in the frontend bundle or source control. The device token lives locally in the installed app and authorizes its own settings. Clearing that app's data requires reconnecting notifications. Use Disconnect before clearing storage where possible.

```sh
npx wrangler login
npm run check:worker
npm run db:migrate
npm run deploy:worker
npm run deploy
# Test the API against a local Worker/D1:
npm run db:migrate:local
npx wrangler dev --port 8787 --test-scheduled
# in another terminal
node scripts/check-reminders.mjs
```

Worker logs/traces are enabled. The scheduler uses at most one delivery attempt per configured period per device per local day. Expired push subscriptions are removed after a 404/410 response. The setup code protects enrollment; device tokens protect schedule changes, and only the Surge origin is allowed by CORS. API responses never expose the private VAPID key or another device's settings.
